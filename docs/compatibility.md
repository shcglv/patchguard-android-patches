# Compatibility

PatchGuard does **not** test patches against target applications. Compatibility is therefore a static assessment, never a runtime guarantee.

## What is assessed

- The patch's declared `Compatibility` block and `AppTarget` entries.
- Declared app versions, version codes, `minSdk`, `apkFileType` and form factor.
- Fingerprints and version gates present in the source.
- The required Morphe Patcher version and the template version.
- Upstream changelogs and metadata, where available.
- Whether the reviewed source revision matches the declared release.

## Labels

| Label | Meaning |
|---|---|
| `DECLARED` | The author declares compatibility. PatchGuard has not independently assessed it. |
| `STATICALLY_ASSESSED` | PatchGuard reviewed the declaration, fingerprints, version gates and metadata. No app was patched or launched. |
| `NOT_RUNTIME_TESTED` | The patch was not run against the target app. This is always true. |

A patch card may show several labels for different versions. None of them means “works”.

## What is not assessed

- Whether a fingerprint matches a specific app build.
- Whether the patch applies without errors.
- Whether the patched app starts, behaves correctly, or preserves data.
- Whether a server-side feature still works.
- Whether the patch is safe on a specific Android version or device.

## Why this is a limitation, not a temporary gap

Static-only is the project's chosen model. The official Morphe patch guidelines recommend `--validate` with Morphe Desktop against target APKs. PatchGuard does not do that, by policy. The resulting limitation is documented on every patch page and in the README.

## Reading a compatibility statement

A correct statement looks like:

> Declared compatibility: app 1.2.3 (version code 1234), `STATICALLY_ASSESSED` from source metadata; `NOT_RUNTIME_TESTED`.

An incorrect statement looks like:

> Works with app 1.2.3.

PatchGuard does not publish the second form.

## Morphe bundle compatibility

PatchGuard's own bundle is built with the official Morphe template and follows its metadata and release conventions. That is **structural** compatibility:

- `.mpp` is produced by the official Gradle build.
- `patches-list.json` and `patches-bundle.json` are generated by the official release workflow.
- Release assets and optional signatures follow the template.
- The source URL is a public GitHub repository.

Structural compatibility does not prove that a patch applies to a given app. Runtime behavior and patch application remain untested.
